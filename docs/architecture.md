# 系統架構

> 狀態：早期原型，文件與程式同步更新。最後檢視：2026-11-05。

## 目標與邊界

Project Nanako 是基於 Electron 的 Windows 桌面延伸作品，提供軟體式、本機優先的檔案管理服務。此版本先完成桌面 UI、帳號／權限、檔案基本操作與本機 API 的垂直切片；不依賴專用硬體或雲端帳號。

目前 HTTP 服務僅可從本機迴圈介面連線。程式會列出網路介面與 IP 作為診斷資訊，但不會綁定網卡、不會開啟防火牆，也不會提供區域網路檔案傳輸。此限制是刻意的原型邊界，不能視為已完成網路共享需求。檔案管理根目錄固定在可攜式執行檔所在位置的 `NanakoData\data`；檔案管理、相簿、播放器與資源回收桶皆共用該受限範圍，不提供 Windows 磁碟瀏覽、Known Folder 選擇或外部資料夾掛載功能。

## 元件

```text
Electron 主程序
  ├─ 建立 BrowserWindow（隔離環境、停用 Node 整合）
  ├─ 啟動同一程序內的 Node.js HTTP 服務
  └─ 關閉視窗時關閉服務與 SQLite
          │ HTTP，127.0.0.1 隨機連接埠
          ▼
Renderer（public/） ─── /api/* ───► HTTP 路由與驗證／授權
                                        ├─ Node.js 內建 SQLite
                                        └─ 本機檔案系統（含 Range 媒體串流）
```

Renderer 的外層以 Nanako 內部桌面呈現捷徑、應用程式入口與本機狀態；應用程式視窗由共用 HTML 範本動態建立，每個應用程式各有一個獨立視窗，並以視窗 Map 管理開啟／最小化狀態、作用中視窗與 z-order。工作列與 Dock 會同步呈現視窗；支援拖曳、方向鍵移動、最小化、最大化／還原、關閉及從工作列還原。視窗生命週期操作會透過本機 `/api/activity` 記錄。功能面板開啟時由隱藏的內容 bank 移入該應用程式視窗，關閉時移回，既有檔案資料操作仍由同一組本機 API 及權限檢查處理。這是應用程式自己的 UI，不會呼叫 Windows Shell。完整操作規則見[桌面互動體驗規劃](ux-interaction-plan.md)。檔案管理支援重新命名、移動、串流複製與逐項批次操作；複製會使用 Nanako 受管理目錄中的隱藏暫存項目，完成後才發布至目的地。重複檔案功能以 Node.js 內建 `crypto` 串流計算 SHA-256，並在確認後將副本移至同一個 Nanako 資料空間的資源回收桶。一般檔案 ZIP 串流建立／解壓縮原型及本機操作紀錄已實作；加密空間仍在規劃，現有一般檔案不能視為已加密。

- `electron/main.mjs`：桌面生命週期、視窗安全設定、啟停 HTTP 服務。
- `src/server.mjs`：本機 HTTP API、登入、權限檢查、操作紀錄、檔案／資源回收桶／ZIP 作業、靜態檔案。
- `src/archives.mjs`：限制 NanakoData 路徑範圍的 ZIP 串流建立與解壓縮、中央目錄／路徑／CRC／大小驗證。
- `src/duplicates.mjs`：限定 NanakoData 範圍的檔案列舉、串流 SHA-256 雜湊、進度回報、取消與重複群組整理。
- `src/file-catalog.mjs`：限定單一 Nanako 資料空間、跳過內部目錄及符號連結的圖片／影音／文件遞迴索引；以目錄串流方式列舉，單次最多檢查 100,000 個項目並回傳 1,000 項。
- `src/run.mjs`：供開發及測試使用的命令列啟動器。
- `public/`：繁體中文（台灣）介面，透過同源 HTTP 呼叫 API。
- `test/`：使用暫存資料目錄的 API 整合測試。

## 資料配置

```text
<dataDir>/
  metadata.sqlite       使用者、分享資料夾、權限、工作階段、操作紀錄與應用程式設定
  files/<share-id>/     分享資料夾內容
  trash/<share-id>/<id> 待清除或還原的檔案
```

Windows 可攜式封裝會將設定檔、工作階段及資料分別放在執行檔旁 `NanakoData/profile`、`NanakoData/session`、`NanakoData/data`。Electron 開發與命令列模式會使用專案目錄內的 `NanakoData/data`。可攜式執行檔需放在目前使用者可寫入的位置；程式不提供資料目錄或磁碟切換選項。部署前仍須確定資料備份／還原與升級流程。

所有分享資料夾的實體根目錄均由伺服器組成為 `dataDir/files/<share-id>`；Renderer 只能傳遞分享 ID 與經驗證的相對路徑，不得傳絕對路徑或磁碟代號。匯入檔案是使用者明確選取後複製至 Nanako 管理目錄；應用程式不提供瀏覽、編輯或刪除匯入來源的功能。資源回收桶固定在 `dataDir/trash/<share-id>/<item-id>`，相簿與媒體預覽也只由相同分享根目錄提供。既有資料若含超出範圍的來源紀錄，啟動時會停用該來源中繼資料並清除對應的舊回收桶路徑，不會沿用、搬移或存取其實體路徑。`xdg-user-dirs` 與 Windows Known Folders 均不作為資料根目錄。

重新命名與移動只接受分享根目錄內的相對路徑；不允許操作分享根目錄、覆寫目的項目、跟隨符號連結或將資料夾放入自身子目錄。複製以串流方式處理檔案，整個資料夾複製前先估算項目數與容量，複製期間排除 Nanako 隱藏暫存名稱及資源回收桶內部資料；暫存複製完成後才重新命名為最終項目。批次操作由前端逐項呼叫 API，部分失敗不會回滾已成功的項目，每項結果各自寫入操作紀錄。

## 驗證與授權

- 首次設定只在尚無使用者時建立本機管理員。
- 密碼使用 Node.js `scrypt` 加上每位使用者的隨機 salt 雜湊。
- 隨機工作階段權杖只以 SHA-256 雜湊值寫入 SQLite；瀏覽器 Cookie 設為 `HttpOnly`、`SameSite=Strict`。
- 管理員可建立一般使用者、修改分享資料夾讀寫權限、停用／重新啟用帳號；停用會撤銷現有工作階段。使用者可自行變更密碼，成功後其他工作階段會撤銷。所有 API 檔案操作都在伺服器端檢查權限。
- 登入失敗依帳號與來源位址節流：15 分鐘內錯誤 5 次後暫停 15 分鐘；狀態暫存在服務程序記憶體，程式重新啟動會清除。
- 管理員限定的電腦資訊 API 會檢查 Windows 系統管理員群組與目前程序完整性等級；使用者帳號具管理員身分不等於程式目前已提升。
- 圖片／音訊／影片透過受權限檢查的 `/api/preview` 提供；支援單一 byte range，以便瀏覽器 seek 影片或音訊。
- Electron renderer 設定 `contextIsolation` 與 `sandbox`，停用 `nodeIntegration`，並拒絕外部視窗與非本機導覽。

尚未實作密碼重設、多因素驗證、使用者刪除、API token 或遠端授權。Windows 系統管理員權限狀態可以檢視，但需要管理員身分安裝的發行安裝程式及一般帳號的權限分離流程仍待設計；可攜式版本不會自行安裝服務或提升權限。操作紀錄由本機管理員控制保留與刪除，不是防竄改帳本；不得將本原型的工作階段設計直接用於對外網路服務。

## 加密與封存演進（尚未實作）

加密空間提案將 vault 密文物件、加密中繼資料與一般 Nanako 檔案區隔；解鎖金鑰由主程序控管，Renderer 不接觸金鑰。格式候選為 Node.js 內建 `crypto` 提供的認證加密原語，並以固定大小區塊維持大檔案串流與受控 Range 讀取。這些只是候選設計，須先完成威脅模型、nonce／AAD 格式審查、復原 UX、篡改測試與 crash-consistency 測試。

ZIP 原型先限定一般 Nanako 檔案並以串流方式建立／解壓，進出路徑固定於 NanakoData。建立與解壓都先寫入範圍內的暫存位置，驗證成功後才提交；伺服器拒絕路徑跳脫、符號連結、Zip Slip、衝突路徑及超限項目。大檔案效能、取消與 Windows 檔案總管互通性仍待驗證。vault 與 ZIP 初期分開，避免誤產生明文暫存。

詳細階段、API 草案、金鑰模型候選及驗收條件見 [加密空間與 ZIP 規劃](feature-plan-encryption-and-archives.md)、[ADR-0009](decisions/ADR-0009-encrypted-vault-design.md) 與 [ADR-0010](decisions/ADR-0010-zip-archive-design.md)。

## 網路與 API 演進

目前 API 與 UI 同源，只供本機用戶端使用；`GET /api/network` 只回報目前服務位址、連接埠及介面清單，並非網路設定功能。網路介面選擇、區域網路共享及 SMB 尚未實作，但 SMB 是產品必要功能。SMB 管理 UI 可參考 SMB 檔案用戶端的檔案操作流程及 Samba 管理介面的服務／分享／帳號狀態呈現；該用戶端不是 SMB Server，Linux Samba 管理流程也不能直接套用 Windows。服務端技術選擇及帳號映射需先完成概念驗證，依 [ADR-0015](decisions/ADR-0015-smb-sharing.md) 與 [SMB 實作規劃](smb-implementation-plan.md) 推進。後續要開放區域網路時，需另行設計並測試：

1. 由使用者明確選取介面／IP、連接埠與是否啟用，預設維持關閉。
2. 避免任意 host、DNS rebinding、跨來源請求及 CSRF；明確驗證 Host、Origin 與授權。
3. TLS 憑證建立／信任、Windows 防火牆規則的建立／移除與錯誤復原。
4. 上傳大小、併發、速率限制、斷線續傳及磁碟空間處理。
5. API 版本、token scope、輪替／撤銷、權限矩陣及 OpenAPI 文件。
6. 網路介面變動、休眠／喚醒、服務重啟與關機的生命週期測試。

未來 API 採本機帳號授權，並提供明確、可撤銷的整合憑證；不導入 SSO 或雲端身份服務作為前提。

## 安全注意事項

目前拒絕路徑跳脫及符號連結，並使用暫存檔完成上傳後再改名；但一般路徑檢查仍可能有檢查與使用間的競爭條件。登入節流目前只在服務程序記憶體中生效，尚無面向網路的防護。開放區域網路前須先完成威脅建模、檔案系統競爭測試、安全測試與獨立檢視。
