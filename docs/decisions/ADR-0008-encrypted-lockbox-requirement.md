# ADR-0008：加密空間與檔案上鎖需求

- 狀態：待設計，尚未實作
- 日期：2026-11-05

加密格式、資料流程與驗收條件另整理於 [加密空間實作規劃](../feature-plan-encryption-and-archives.md) 與 [ADR-0009](ADR-0009-encrypted-vault-design.md)。

## 背景

使用者希望有類似「加密空間」的功能；上鎖後的檔案不能只在 Nanako 介面隱藏，Windows 檔案總管也不應能直接開啟原始內容。

## 需求決定

- 上鎖內容必須在可攜式 `NanakoData` 範圍內以加密格式保存；檔案總管讀取儲存檔時只能取得密文。
- 只使用隱藏檔、NTFS ACL、改副檔名或 UI 權限都不算加密上鎖。
- Nanako 解鎖後才可依使用者權限檢視、播放或匯出；明文不得為方便而落地到暫存檔。
- 相簿、播放器與資源回收桶仍須限制在 Nanako 可攜式資料範圍，並明確定義加密項目的鎖定、刪除與還原狀態。

## 尚待設計

- 金鑰建立、密碼變更、忘記密碼及備份／復原方式。
- 串流加密格式、完整性驗證、超大檔案與媒體 Range 讀取。
- 多位本機使用者的金鑰隔離、閒置自動鎖定與記憶體金鑰清除。
- 匯出明文的授權提示，以及作業系統管理員／惡意程式威脅邊界。

在上述設計與測試完成前，不把既有一般檔案稱為已上鎖或已加密。
