# ADR-0010：ZIP 壓縮與解壓縮原則

- 狀態：已採納並完成第一版原型；互通性與大檔案驗證仍進行中
- 日期：2026-11-05

## 背景

使用者已確認開始規劃檔案壓縮。大檔案不應整份載入記憶體，而且 Nanako 的管理範圍只能是可攜式執行檔旁的 `NanakoData`。

## 提案

1. 已提供 ZIP 建立與解壓縮至新資料夾；輸入、輸出與暫存都只在 NanakoData 內。
2. 已採串流處理，不把單一檔案或完整 ZIP 載入記憶體；取消與進度尚未實作。
3. 建立 ZIP 使用同目錄隨機暫存檔，成功收尾後才改名；解壓縮使用 NanakoData 內隔離暫存目錄，完整通過驗證後才改名至目的資料夾。
4. 預設不覆寫；拒絕 ZIP Slip、絕對／UNC／磁碟路徑、符號連結、重複／衝突路徑、不合規 CRC 及超出限制的封存檔。
5. 加密空間與一般 ZIP 操作先分開交付；不得在解壓或封存過程中於磁碟留下 vault 明文。
6. 採用單一套件 [zip.js](https://github.com/gildas-lormeau/zip.js/) 2.24.0；以懶載入 BlobReader、串流讀寫、ZIP64 與 CRC 檢查支援本機原型。
7. 已更新 `THIRD_PARTY.md`、`package.json` 與鎖檔，記錄版本、BSD-3-Clause 授權與封裝狀態。

## 後續工作

已加入小型 ZIP 建立／解壓整合測試與 ZIP Slip 拒絕測試。後續需建立大型 ZIP 與更多惡意封存測試矩陣，量測記憶體並驗證取消、損毀 CRC 與 Windows 檔案總管互通性；通過前不可宣稱完成正式封存功能。
