# ADR-0010：ZIP 壓縮與解壓縮原則

- 狀態：提案，等待串流原型與安全測試
- 日期：2026-11-05

## 背景

使用者已確認開始規劃檔案壓縮。大檔案不應整份載入記憶體，而且 Nanako 的管理範圍只能是可攜式執行檔旁的 `NanakoData`。

## 提案

1. 第一版先提供 ZIP 建立與解壓縮至新資料夾；輸入和輸出都只在 NanakoData 內。
2. 以串流處理，不把單一大檔或整個 ZIP 一次讀入記憶體；提供進度與取消。
3. 建立 ZIP 使用同目錄暫存檔，成功收尾後才改名；解壓縮使用 NanakoData 內隔離暫存目錄，完整通過驗證後才移入目的資料夾。
4. 預設不覆寫；拒絕 ZIP Slip、絕對／UNC／磁碟路徑、符號連結、重複衝突路徑、不合規 CRC 及超出政策限制的封存檔。
5. 加密空間與一般 ZIP 操作先分開交付；不得在解壓或封存過程中於磁碟留下 vault 明文。
6. 先作免新增依賴的串流 PoC；若需套件，優先評估單一能支援必要建立／解壓串流的套件。候選 zip.js、Archiver、yauzl 均未採用，需檢查實際授權、維護狀態、Zip64 及 Windows 互通性。
7. 只有正式採用依賴時才更新 `THIRD_PARTY.md`、`package.json` 與鎖檔。

## 後續工作

建立實際大型 ZIP 與惡意封存測試矩陣，完成記憶體、取消、CRC／路徑安全與 Windows Explorer 互通性驗證，再決定 API、UI、上限與套件。
