# ADR-0015：Windows SMB 區域網路分享

- 狀態：已接受需求與安全邊界；實作技術尚未通過原型驗證
- 日期：2026-11-05

## 背景

Nanako 是以 Windows 電腦提供類 NAS 體驗的 Electron 延伸作品。使用者明確要求網路分享與 SMB 必須納入產品，不可只做本機檔案服務或把 SMB 當成可選功能。Nanako 目前有本機帳號與分享資料夾讀寫權限；另有預設關閉的 HTTPS 網頁 LAN 存取，讓其他裝置透過瀏覽器介面登入並上傳／下載授權檔案。此 Web 存取不提供 SMB 協定或檔案總管網路分享，SMB 伺服器仍未實作。

使用者提供的兩個參考專案定位不同：

- [smbwebclient](https://github.com/vmvarela/smbwebclient) 是連線至既有 SMB/CIFS 分享的網頁用戶端，具檔案管理操作流程參考價值，但本身不是 SMB 伺服器。
- [Samba-Manager](https://github.com/lyarinet/Samba-Manager) 是 Linux Samba 管理介面，可參考分享管理、使用者權限、服務狀態、紀錄與初始設定的資訊架構；其 Linux Samba 管理方式不能直接套用至 Windows。

兩個參考專案目前只供介面與流程研究，沒有使用其原始碼或資產，故不列入 `THIRD_PARTY.md`。

## 決策

1. **SMB 是正式產品需求**，以預設關閉、管理員明確啟用的區域網路服務方式規劃。之後可分階段實作，但不得將其從版本規劃移除或描述為非必要功能。
2. SMB 分享只能映射至 Nanako 管理的 `NanakoData\data\files\<share-id>` 根目錄。不得分享 NanakoData 上層、其他磁碟、Windows 個人資料夾或任意路徑；資源回收桶、帳號資料庫、操作紀錄與暫存檔不得透過 SMB 洩漏。
3. SMB 認證與檔案權限必須保留 Nanako 帳號及每個分享資料夾既有的讀取／寫入授權語意；訪客／匿名與全域可寫分享預設禁止。不得以「隱藏檔案」或只在 UI 隱藏項目替代伺服器端授權。
4. 高權限操作須交由明確受控、操作範圍受限的 Windows 安裝服務／管理員代理程式；不得讓 Electron Renderer 或一般本機 HTTP API 執行任意 PowerShell、任意檔案路徑或未驗證的系統管理指令。可攜式執行與一般帳號使用流程須與權限提升分離，依 ADR-0013 驗證。
5. SMB、Nanako 網頁服務及管理 API 的監聽位址與連接埠分開管理。SMB 連接埠不得假裝可任意設定：一般 SMB 用戶端的標準連線使用 TCP 445，替代連接埠須先驗證各平台用戶端的連線方式與相容性。網卡選擇必須實際限制監聽介面，不可只改 UI 顯示。
6. 實作前先做 SMB 引擎概念驗證，確認 SMB2／SMB3 交涉、安全簽章／加密能力、逐使用者認證與權限、NanakoData 路徑隔離、重新命名／移動／檔案鎖定等操作，以及 Windows、macOS、Linux 用戶端相容性。未通過安全與互通測試前，不得標示 SMB 已可供正式使用。
7. SMB 管理介面應借鏡參考專案的管理資訊架構，至少呈現服務啟停與狀態、分享清單、各帳號授權、使用中的網路介面／連接資訊、錯誤與管理操作紀錄，以及清楚的啟用／停用確認流程。

## 尚待驗證的實作選擇

- Windows 內建 SMB 伺服器可提供原生相容性，但需要釐清 Windows 身分與 Nanako 本機帳號如何安全映射、如何在不放寬 NTFS ACL 的前提下維持逐使用者權限，以及如何透過管理員安裝服務受控管理分享。
- 自行封裝的 SMB2／SMB3 伺服器可使用 Nanako 認證與虛擬檔案系統介面，但必須評估專案成熟度、協定覆蓋、相容性、安全維護成本、授權與封裝方式。
- 不把網頁 SMB 用戶端誤認為 SMB 伺服器，也不因 Samba 管理 UI 使用 Linux 指令就將 Samba／Linux 執行環境直接帶入 Windows 可攜式程式。

選定且實際採用第三方程式碼或套件時，才依維護規範將專案、鎖定版本、用途、授權與封裝狀態加入 `THIRD_PARTY.md`。

## 目前已實作的前置項目

管理員可在 Nanako「網路狀態」檢視 Windows SMB Server 服務狀態、TCP 445 是否有人監聽、`New-SmbShare` 命令是否可用，以及 Nanako 程序是否已提升。該檢查使用唯讀 PowerShell 查詢；不建立／移除 Windows 分享、不啟停 `LanmanServer`、不設定防火牆，也不代表 Nanako SMB 分享已可用。HTTPS 網頁 LAN 登入是一項獨立功能，提供瀏覽器檔案上傳／下載，但不提供 Windows 檔案總管 SMB 協定服務。SMB 引擎、分享管理與逐帳號認證仍未實作。

目前網路狀態頁另提供預設關閉的實驗性 SMB 選擇：只有產品識別為 Windows 11 且 build ≥ 26100（24H2+）才可勾選；舊版、非 Windows 與無法確認版本時皆禁用，API 會再次檢查資格。此旗標只保存使用者選擇，不表示引擎、listener 或 Windows 分享已啟動。

Nanako 已將讀取／寫入授權判斷集中到共用政策函式，並由現有檔案 API 與測試使用；另已建立 SMB 正規化檔案操作到既有每分享讀寫授權的明確映射，未知操作拒絕。SMB 引擎候選的 Windows 相容性與權限缺口記錄於 [`docs/smb-prototype-results.md`](../smb-prototype-results.md)。這些政策不代表 SMB 協定服務已啟動。

## 驗收條件

1. SMB 預設關閉，使用者可在 Nanako 管理介面明確啟用、停用並查閱實際服務狀態。
2. 管理員可選擇已連線的 Windows 網路介面；實測確認其他未選介面無法連線。
3. SMB 客戶端登入使用 Nanako 帳號／明確設定的 SMB 憑證；每位使用者只能讀寫獲授權的分享資料夾。
4. 分享根目錄、路徑正規化、重新解析點／符號連結與保留系統資料皆由服務端強制防護。
5. 支援的 SMB 協定版本、簽章／加密狀態與連線方式均可從管理介面辨識；停用 SMB 後確認監聽器停止且分享不再可連線。
6. Windows 檔案總管、至少一種 macOS SMB 用戶端與 Linux `smbclient` 的讀取、寫入、重新命名、移動、刪除／資源回收語意均完成測試。
