# ADR-0014：受管理資料空間內的檔案操作

- 狀態：已採用（原型）
- 日期：2026-11-05

## 背景

檔案管理原型已可瀏覽、匯入、下載與使用資源回收桶，但缺少重新命名、移動、複製與批次操作。使用者要求 Nanako 的檔案管理器只能操作可攜式程式位置內的 `NanakoData`，不能加入 Nanako 自身資料目錄／其上層或其他磁碟作為來源。

## 決策

1. 所有新增 API 只接受分享資料空間內的相對路徑與既有分享 ID；重新命名、移動、複製及批次操作都不得改變固定的 `NanakoData` 根目錄。
2. 重新命名與移動拒絕根目錄、符號連結、特殊檔案、目的地同名項目及資料夾移入自身子資料夾；不提供覆寫模式。
3. 複製檔案以 Node.js streams 複製，不把檔案整份載入記憶體。複製資料夾時先計算項目數及檔案大小、檢查 Nanako 資料目錄所在磁碟的可用容量，再複製到目的資料夾下的隱藏暫存項目；完成後才重新命名發布。失敗時清除暫存項目。
4. 單次複製最多處理 100,000 個項目；拒絕符號連結與特殊檔案，並排除 Nanako 隱藏暫存名稱及回收桶內部資料。資料夾不能複製到自己或其子資料夾。
5. 批次操作由 UI 逐項呼叫單項 API；每個項目分別授權、驗證、回應及記錄。部分失敗不回滾先前成功項目，UI 顯示部分完成結果。
6. 本階段不引入新套件。進度、取消、大型檔案／資料夾記憶體與效能量測、磁碟空間競態及作業復原列為後續驗證。

## 後果

- 一般使用者可在 Nanako 內完成常見檔案整理，不需開啟 Windows 檔案總管，也不會因此取得外部資料夾存取能力。
- 隱藏暫存路徑會被檔案 API 隱藏及拒絕直接存取，避免使用者將未完成複製當成正常資料。
- 目前批次操作不是整批交易；成功的項目會保留，即使後續項目失敗。
- 初版不宣稱已支援大型資料夾取消、進度顯示、磁碟容量變動時的完整保護或跨程序競態保證。

## 驗收

- API 整合測試涵蓋檔案重新命名、同名衝突、移動、目錄自我巢狀拒絕、檔案／資料夾串流複製、空資料夾、容量／項目回應、保留路徑隱藏與唯讀權限拒絕。
- Renderer 提供單項重新命名及多選後批次移動、複製、移至資源回收桶。
- 操作紀錄逐項保留每個檔案操作的目標與成功／失敗結果。
- 所有路徑解析沿用伺服器 Nanako 資料範圍與符號連結拒絕檢查。
