# ADR-0013：Windows 系統管理員安裝與執行權限

- 狀態：需求已記錄；安裝／執行架構尚待實作
- 日期：2026-11-05

## 背景

產品需求指定 Nanako 需要 Windows 系統管理員權限，管理員介面必須能查看目前執行環境是否已提升；正式安裝流程須以具 Windows 系統管理員身分的帳號完成，日常 Nanako 使用者不應被要求了解安裝或提升權限細節。

Nanako 同時要求可攜式、隨選隨用，並將所有資料限制在可攜式程式位置的 `NanakoData`。目前只有 Electron Windows x64 portable 封裝，沒有安裝程式；Electron 與本機 HTTP 服務目前在同一個使用者程序內執行。

## 已採用決策

1. 僅本機管理員可查看的「電腦資訊」應顯示目前 Windows 身分、是否屬於系統管理員群組，以及目前程序是否處於 High／System Integrity 等級。管理員帳號成員身分與目前程序是否已提升需分開呈現。
2. 權限檢查結果由 Windows token 的完整性等級判斷，不只依賴帳號名稱或 Nanako 內的 `admin` 角色。
3. 不得將 NanakoData 移出使用者選定的隨選隨用程式位置，也不得因安裝流程而擴大檔案管理根目錄。

## 尚待實作的發行需求

- 建立需由 Windows 系統管理員帳號完成的安裝流程，並提供可攜式發行檔的明確定位與差異。
- 定義一般 Windows 帳號使用 Nanako 的方式，不要求一般使用者自行操作「以系統管理員身分執行」或輸入不應知悉的管理員憑證。
- 目前單一 Electron 程序無法同時保證一般帳號免提升、後端具最高權限、資料仍位於可攜式目錄。需先設計並驗證權限分離的後端服務／受控提升流程、啟停生命週期與 NanakoData ACL，再決定是否採用 Windows 服務或其他架構。
- 不應只把執行檔 manifest 設為 `requireAdministrator` 就宣稱符合需求：標準 Windows 帳號每次啟動都可能被要求提供管理員憑證，與日常使用需求衝突。

## 驗收條件

1. 安裝程式明確要求管理員身分，且可驗證安裝者／安裝位置與資料目錄權限。
2. 標準 Windows 帳號能依設計啟動與使用 Nanako，不需自行處理提升權限或取得管理員憑證。
3. 管理員介面能清楚顯示 Nanako 後端實際執行身分、權限層級與服務狀態；不得把 Nanako 管理員角色誤稱為 Windows 系統管理員。
4. 啟動、關閉、崩潰復原、休眠喚醒、解除安裝與 portable 模式均不越出 NanakoData 範圍，並通過 Windows 測試。
