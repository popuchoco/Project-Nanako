# SMB 區域網路分享實作規劃

此功能是 Nanako 的必要範圍，但目前版本尚未開放區域網路或 SMB 連線。本文件拆分實作階段與驗收條件；進度只有在服務端、UI 與跨裝置測試通過後才會更新為完成。

## 參考專案的適用範圍

| 專案 | 專案本身的角色 | Nanako 可參考之處 | 不直接套用之處 |
| --- | --- | --- | --- |
| [smbwebclient](https://github.com/vmvarela/smbwebclient) | 使用者登入既有 SMB 分享後，以網頁操作遠端檔案的 SMB 用戶端 | 檔案清單、上傳／下載、建立資料夾、刪除、重新命名與連線憑證流程 | 它不會在 Nanako 主機建立 SMB 分享；Nanako 已有檔案管理器，不能以此替代 SMB Server |
| [Samba-Manager](https://github.com/lyarinet/Samba-Manager) | 管理 Linux Samba 設定與服務的 Web 管理介面 | 分享管理、使用者授權、服務狀態、紀錄、設定驗證與初始設定流程 | Linux Samba、Linux 帳號／群組、`smb.conf` 與服務管理命令不直接相容於 Nanako 的 Windows 架構 |

參考專案的原始碼與資產未匯入本專案；目前不列入 `THIRD_PARTY.md`。

## 階段一：SMB 伺服器概念驗證

- 評估 Windows 內建 SMB 與可封裝的 SMB2／SMB3 Server 兩條路線，不以 SMB 用戶端套件充當 Server。
- 用小型 NanakoData 測試目錄驗證協定交涉、檔案列舉、讀取／寫入、建立目錄、重新命名、刪除、並行連線、檔案鎖定與斷線復原。
- 驗證使用者權限映射：同一 SMB 連線不得因知道其他分享名稱或路徑而跨越 Nanako 帳號授權。
- 驗證伺服器端排除資源回收桶、操作紀錄、資料庫、密碼雜湊與任何暫存項目。不可只依賴隱藏屬性或 Renderer 過濾。
- 比較 Windows 11 檔案總管、macOS Finder 與 Linux `smbclient`；記錄 SMB dialect、簽章／加密協商及效能結果。
- 只有確定實際採用第三方原始碼／套件後才更新 `THIRD_PARTY.md`，列明實際版本、授權及發行檔是否包含。

## 階段二：Windows 權限分離與服務控制

- 依 ADR-0013 先完成管理員安裝的服務／代理程式設計與一般 Windows 帳號操作模型。
- 高權限元件只接受固定命令集合與識別碼，不接受 Renderer 提供的任意指令或實體路徑。
- 使用受 ACL 保護的 IPC 傳遞啟停、網卡設定、分享設定與服務狀態；驗證呼叫者 Nanako 角色及 Windows 身分。
- SMB 關閉時確認所有 listener、Windows 防火牆例外與暫存憑證均已停用／清除；解除安裝時只移除 Nanako 建立的設定。

## 階段三：Nanako 內的 SMB 管理介面

- 服務預設關閉，管理員清楚確認後才能啟用。
- 顯示 SMB Server 狀態、服務身分、支援的 SMB 版本、實際監聽 IP／連接埠、連線錯誤及近期操作紀錄。
- 提供網卡／IP 選擇、SMB 分享清單，以及每個 Nanako 使用者的唯讀／讀寫權限；權限變更立即同步至服務端。
- 只允許選取 Nanako 分享資料夾識別碼，不提供路徑選擇器、磁碟機清單或上層目錄輸入。
- 對啟用、停用、刪除分享與撤銷權限提供確認及結果回報。

## 連接埠與用戶端相容性

SMB Server 的監聽連接埠與 Nanako 管理網頁連接埠是兩個不同設定。正式 SMB 連線一般使用 TCP 445；若為避免和 Windows 內建檔案伺服器衝突或符合可攜式模式而採替代連接埠，須記錄 Windows、macOS、Linux 各用戶端的連線指令與限制，不能只依 Server 啟動成功就宣稱可用。所有連線連接埠預設不開放，並且不得自動設定路由器連接埠轉送。

## 暫不宣稱完成

以下任一項尚未通過前，SMB 仍標示為「尚未實作／測試中」：使用者對應授權、資料範圍隔離、Windows 高權限服務安全、實際網卡繫結、SMB 協定安全協商、跨作業系統用戶端互通、停止服務後連線失效，以及可攜式封裝測試。
