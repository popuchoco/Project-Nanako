# 介面與互動設計

> 狀態：第一版功能原型。UI 用語採繁體中文（台灣）；細節依實際使用者測試調整。

## 設計原則

1. **先看懂狀態，再執行動作**：清楚呈現目前登入者、所選分享資料夾、所在路徑及讀寫權限。
2. **破壞性操作可復原**：一般刪除先移到資源回收桶；永久刪除需管理員操作並明確確認。
3. **權限不可只靠 UI**：隱藏或停用按鈕只是提示，API 必須重新檢查使用者權限。
4. **本機優先、無雲端依賴**：登入、檔案與設定均在本機處理；不暗中建立遠端帳號或同步。
5. **以台灣慣用語呈現**：所有 UI 訊息、錯誤說明、文件都使用繁體中文（台灣）詞彙。
6. **桌面外觀只在 Nanako 視窗內模擬**：仿桌面工作列、捷徑及應用程式視窗是 Nanako 的介面，不接管 Windows 桌面、不操作 Windows Shell。

## 目前主要畫面

- **Nanako 桌面**：在 Nanako 視窗內提供桌面捷徑、應用程式選單、頂端工作列、Dock 與時鐘；各應用程式可在自己的 Nanako 內部視窗中開啟，並支援前景排序、拖曳、最小化、最大化／還原與關閉。關閉內部視窗不會關閉服務或 Windows；同一應用程式重複啟動會切回既有視窗。主要視窗操作也會寫入使用者操作紀錄。完整互動規則見 [桌面互動體驗規劃](ux-interaction-plan.md)。
- **初始設定／登入**：僅建立本機管理員與本機帳號登入。密碼要求至少 12 個字元。
- **檔案管理**：以獨立視窗呈現 Nanako 檔案位置、圖片／影片／音訊／文件分類、檔名搜尋與排序；分類可遞迴搜尋目前選取的 Nanako 資料空間，並顯示檔案的 Nanako 相對位置，分類結果只能開啟，不直接提供移動、重新命名或刪除操作；一般檔名搜尋限目前資料夾。只瀏覽可攜式執行檔旁 `NanakoData` 內的 Nanako 資料空間；支援建立資料夾、匯入（複製）檔案、下載及移至資源回收桶。匯入來源不會成為可瀏覽或管理的資料夾。
- **相簿**：只瀏覽 Nanako 資料空間中的圖片；預設可搜尋整個資料空間並檢視全螢幕圖片，也可切換至資料夾導覽。結果最多顯示 1,000 張並標示 Nanako 相對路徑；目前直接由瀏覽器載入原圖，尚未產生縮圖。
- **播放器**：只列出 Nanako 資料空間中的影音檔；預設提供整個資料空間的音訊／影片播放清單及檔名搜尋，也可切換至資料夾瀏覽。結果最多顯示 1,000 項並標示相對路徑；使用瀏覽器原生控制項，格式解碼能力依 Electron 內建 Chromium 而異。
- **資源回收桶**：只檢視及還原 Nanako 資料空間內刪除的項目；只有管理員可永久刪除。
- **使用者與權限**：管理員新增使用者並設定分享資料夾讀取／寫入權限。
- **網路狀態**：目前只顯示本機服務狀態及網卡診斷資訊，不提供連線設定。
- **我的電腦**：顯示目前登入者有權存取的 Nanako 資料空間，不會列出 Windows 磁碟、個人資料夾或任意路徑。
- **電腦資訊**：管理員可檢視 Windows／處理器／記憶體／資料磁碟與網路介面狀態。
- **系統設定與操作紀錄**：管理員可查看所有使用者的操作紀錄，選擇 1／3／7／30／90／180／365 日保留期限，並透過輸入確認文字的防呆視窗手動清空全部紀錄。
- **影音格式相容性**：顯示 Electron／Chromium 宣告的格式能力，並允許使用者從 Nanako 資料空間選取影音檔執行播放測試；不開啟外部檔案選擇器、不瀏覽其他磁碟，也不轉換來源檔。
- **重複檔案整理**：只掃描 `NanakoData`，依檔案內容辨識重複項，讓使用者逐組指定保留檔案，確認後把副本移至 Nanako 資源回收桶；掃描不會修改檔案，並可取消。沒有任選磁碟／資料夾掃描入口。大型資料量及中斷復原仍待驗證。見 [重複檔案整理規劃](feature-plan-duplicate-files.md)。

## 操作與回饋

- 成功、失敗、空清單與載入狀態均提供可理解的文字回饋。
- 檔案名稱以文字節點呈現，不將檔名直接插入 HTML。
- 表格標題與輸入欄位提供語意標記；鍵盤可操作主要按鈕與表單。
- UI 會依 `canWrite` 隱藏寫入動作，但伺服器仍獨立執行授權檢查。

## 視覺方向與參考取捨

- 桌面延續目前的海岸桌布、淺色應用程式視窗與清楚的藍色主動作；未來可提供少數高對比、低干擾的主題選擇，維持一致的圖示比例與字級，不讓主題改變資料操作層級。
- 已將桌面、狀態卡片與啟動器統一為海岸藍／淺色視覺；桌面狀態小工具呈現本機時間、本帳號可用的 Nanako 資料空間數量與本機服務狀態，並提供前往儲存空間視窗的捷徑。窄版畫面隱藏小工具，避免遮擋桌面捷徑。
- 應用程式啟動器保留完整格狀 App Drawer，並在上方提供檔案管理、相簿、播放器的快速啟動列。這借鏡 PieLauncher 的「少數常用入口快速辨識」，但不採用環形手勢；完整清單與鍵盤操作持續可用。
- 以 OmaLauncher 的主題一致性與 HTCHome 的桌面資訊小工具感作風格觀察，不採用 Android／Linux 平台功能；不複製任何參考專案的程式碼或資產。
- 桌面資訊小工具只呈現 Nanako 本機已知狀態；不為了視覺完整而新增天氣、雲端同步或遠端追蹤服務。
- 參考來源與「未使用原始碼、不列第三方」規則見[介面與產品設計參考](design-references.md)。

## 未來需求（尚未完成）

- **加密空間／檔案上鎖**：上鎖內容必須在 Nanako 資料目錄中以加密資料保存，使 Windows 檔案總管直接開啟時只能取得密文；不能只靠隱藏檔案或 NTFS 權限。需先設計金鑰建立／解鎖／鎖定、記憶體金鑰生命週期、串流加解密、檔名與中繼資料保護、復原／備份，以及相簿和播放器的受控解密流程。目前尚未實作，既有 Nanako 檔案仍是一般檔案。
- **ZIP 壓縮／解壓縮**：一般檔案 ZIP 串流原型已實作，限定 NanakoData 範圍並拒絕路徑跳脫／符號連結／覆寫，採暫存與 CRC 驗證後提交；仍需完成互通性、大檔案與 zip bomb 安全測試。加密空間初版與 ZIP 操作分開，避免明文暫存。
- 上述功能的資料模型、API 草案、威脅邊界與驗收條件見[實作規劃文件](feature-plan-encryption-and-archives.md)及 [ADR-0009](decisions/ADR-0009-encrypted-vault-design.md)、[ADR-0010](decisions/ADR-0010-zip-archive-design.md)。
- 可攜式升級保留資料與復原流程。
- 區域網路連線的啟用開關、網卡/IP 選擇、連接埠設定、連線狀態與複製連線資訊。
- 縮圖快取、轉碼策略、字幕與播放進度記錄。
- API Token 管理、API 文件與整合範例。
- SMB 是本專案的必要功能，依網路／權限安全與 Windows 服務分離條件分階段實作；不是可有可無的選項。
