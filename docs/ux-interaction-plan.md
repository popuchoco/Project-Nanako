# Nanako 桌面互動體驗規劃

> 狀態：重新規劃中；本文件定義目標互動模式，不代表所有項目已實作。介面用語採繁體中文（台灣）。

## 產品模型

Nanako 是在單一 Electron 視窗內模擬桌面作業系統的本機檔案服務，不是把所有功能堆在一張管理頁面，也不接管 Windows 桌面。使用者從 Nanako 桌面啟動應用程式，在桌面內的個別視窗完成工作；視窗、導覽列與圖示只能呈現 Nanako 自己管理的功能及資料。

### 不可違反的產品邊界

- 檔案、相簿、播放器、資源回收桶、ZIP、重複檔案整理與加密空間都只能存取可攜式執行檔旁的 `NanakoData`。
- 不列出或導覽 C:、其他磁碟、Windows 已知資料夾或任意外部資料夾；不把來源路徑掛載成 Nanako 空間。
- 「匯入檔案」是一次性複製動作，不是開啟來源目錄；匯入完成後，Nanako 只管理自己的副本。
- 桌面視覺可仿作業系統的工作列、捷徑、應用程式選單與內部視窗，但關閉 Nanako 內部視窗不會停止本機服務或關閉 Windows。
- 本機帳號與權限為主，不依賴雲端帳號或 SSO。SMB 是必要功能規劃，不是可有可無的外掛；啟用及權限操作只由明確授權的管理員控制。

## 觀察到的互動模型

目前參考畫面呈現桌面背景、頂端全域列、桌面應用程式捷徑，以及可獨立操作的檔案管理／檔案去重視窗。檔案管理視窗內再提供側邊導覽、分類檢視與檔案工作區；檔案去重則先說明用途，再引導開始掃描。這種「桌面 → 應用程式視窗 → 應用程式工作區」的分層值得採用。

某些既有產品會在「我的電腦」列出 Windows 磁碟代號，也會要求使用者任選資料夾進行去重；Nanako 不採用這兩種資料存取行為。Nanako 的桌面只呈現自身應用程式捷徑；儲存空間畫面只顯示 `NanakoData` 用量；去重功能固定掃描 Nanako 管理範圍，不提供 Windows 資料夾挑選器。

## 目前原型與目標的差距

目前已有桌面背景、捷徑、應用程式選單、工作列、可移動／最小化／最大化／關閉的內部視窗外觀，以及檔案、相簿、播放器等頁面。不過目前各功能仍共用單一 `#app-window`，切換側邊導覽就更換該視窗內容；這還不是每個應用程式各有視窗、可同時開啟與切換的桌面工作階段。目標互動須以實際多視窗模型取代「單視窗內換頁」模型，並保留既有權限與 `NanakoData` 範圍限制。

## 目標資訊架構

### Nanako 桌面

- **頂端全域列**：應用程式選單、已開啟應用程式／工作區切換、服務本機狀態、帳號，以及管理員可見的系統設定入口。
- **桌面捷徑**：檔案管理、相簿、播放器、資源回收桶、儲存空間、加密空間及管理員工具。只有已實作或清楚標示規劃中的功能可出現；不製作 Windows 磁碟捷徑。
- **工作列／Dock**：顯示執行中的 Nanako 應用程式及作用中狀態。再次選取已開啟的應用程式會將原視窗帶到前景，不建立重複視窗。
- **登入後入口**：以 Nanako 桌面為起點；首次使用時可顯示本機資料空間導覽，但不自動開啟多個功能視窗。

### 內部應用程式視窗

- 每個應用程式都有自己的標題、內容與最小化／最大化還原／關閉控制；作用中視窗有清楚的前景層級。
- 拖曳、最大化及還原後保留可預期的視窗位置。關閉只關閉該 Nanako 視窗；最小化保留工作狀態並可從工作列還原。
- 視窗控制有可見焦點、鍵盤替代操作及一致的無障礙名稱；不要求使用者必須拖曳才能操作。
- 若視窗內容正有未完成的上傳、壓縮或其他工作，關閉前說明工作是否會取消；不得靜默丟棄進度。

### 檔案管理器

側邊導覽只列 Nanako 內的虛擬位置與功能：

- 我的檔案、公共空間。
- 分類檔案：圖片、影片、音訊、文件。
- 最近上傳、我的分享、我的最愛、標籤。
- 資源回收桶、檔案去重。

工作區提供返回／前進、重新整理、Nanako 相對路徑麵包屑、搜尋、排序、清單／網格切換、匯入檔案、新增資料夾與選取後的情境操作。工具列只顯示目前位置和權限允許的動作；沒有權限時說明原因，不以失效按鈕或隱藏錯誤代替回饋。所有路徑都是 Nanako 內部相對路徑，畫面不顯示或接受磁碟代號及外部絕對路徑。

### 重複檔案整理

- 從檔案管理側邊導覽開啟獨立的 Nanako 內部視窗；開始畫面直接說明掃描範圍固定為 `NanakoData`，不顯示「任選資料夾」的按鈕。
- 開始掃描前揭露工作內容；掃描唯讀、可取消、顯示進度。依檔案內容比對，不只依名稱或大小判定。
- 結果以重複群組呈現相對路徑、大小、修改時間與可回收容量；使用者必須逐組指定保留項目。
- 整理前預覽將移除的副本，經明確確認後移到 Nanako 資源回收桶；不自動挑選、不直接永久刪除，並記錄每一筆成功／失敗結果。
- 詳細驗收與邊界見 [重複檔案整理規劃](feature-plan-duplicate-files.md)。

### 相簿、播放器、資源回收桶與管理工具

- 相簿與播放器以一致的 Nanako 路徑導覽，媒體點選後在 Nanako 內檢視／播放，不把來源檔交給外部程式開啟。
- 資源回收桶清楚分開「還原」與「永久刪除」；永久刪除必須明確確認並受管理員／權限規則保護。
- 「儲存空間」呈現 NanakoData 容量及管理範圍，不等同 Windows「我的電腦」或磁碟瀏覽器。
- 電腦資訊與管理員功能只對管理員顯示；一般使用者不必處理程式提升、安裝服務或 Windows 權限細節。
- 網路／SMB 管理功能日後放在清楚的管理員設定區，顯示實際綁定介面、連接埠與連線狀態；目前不可用的控制不得偽裝成已啟用。

## 一致互動規則

- 主要操作使用明確動詞，例如「匯入檔案」、「移至資源回收桶」、「還原」、「開始掃描」；避免「更多」中藏入高風險操作。
- 載入中、成功、失敗、空狀態、權限不足、取消及部分成功都要在原視窗內有可理解的回饋；長時間工作顯示進度與取消能力。
- 破壞性操作在執行前說明影響範圍與可復原性；取消是預設焦點，不在載入完成後自動觸發動作。
- 滑鼠與鍵盤操作等價：Tab 順序符合畫面順序，焦點清楚，Enter／Space 可啟動按鈕，Esc 可關閉可取消的對話框；不以拖曳作為唯一操作方式。
- 圖示按鈕有可理解的無障礙名稱；狀態不只靠顏色傳達。遵守可讀對比、足夠點擊目標、`prefers-reduced-motion` 與語意化 HTML。
- 搜尋、選取、切換檢視、麵包屑與關閉視窗等常見操作不造成意外清除選取、重新播放或資料異動。

## 推進順序

1. **桌面與視窗模型**：拆分目前單一應用程式容器，落實每個 Nanako 應用程式的視窗狀態、前景排序、工作列、重複開啟規則及鍵盤控制。
2. **檔案管理導航**：重整側邊導覽與工具列，移除會被理解為 Windows 磁碟入口的「我的電腦」呈現；只保留 `NanakoData` 內的虛擬位置。
3. **情境操作**：統一單筆／批次操作、確認、進度、取消、錯誤復原與操作紀錄。
4. **媒體及回收流程**：在多視窗模型下驗證相簿、播放器、資源回收桶仍在 Nanako 範圍內並可還原。
5. **重複檔案整理**：依專屬規劃完成唯讀掃描、人工選擇保留項、可復原整理與大型檔案測試。
6. **網路與 SMB**：在必要的管理員安裝與權限分離完成後，才將服務狀態與管理操作接入桌面工作流程；未通過協定與跨裝置測試前維持未啟用。

## 設計系統取捨

UI/UX 指引搜尋結果未找到適合 Windows 仿桌面檔案管理器的精確版型，因此不直接套用行銷頁或 SaaS 儀表板模板。視覺延續 Nanako 現有冷色桌面、淺色視窗與清楚藍色主動作；使用簡潔扁平表面及有限陰影來區分桌面、視窗、內容與對話框。這是依現有介面與產品情境制定的 fallback，不是套件或第三方資產採用紀錄。
