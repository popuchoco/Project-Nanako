# 重複檔案整理

本文件記錄檔案去重的範圍、操作方式與驗收條件。第一版已完成可使用的掃描與回收流程；大容量資料、取消時序、磁碟競態與長時間效能仍需持續驗證。

## 目前實作

- 檔案去重入口位於 Nanako 內部介面，範圍只能選取 Nanako 管理的資料空間，不提供 Windows 資料夾挑選器或其他磁碟入口。
- 掃描先以檔案大小篩選，再以 Node.js 內建 SHA-256 串流雜湊確認內容；單次最多檢查 100,000 個項目，同一位使用者同時只能執行一項掃描。
- 掃描略過 Nanako 資源回收桶、內部暫存項目、符號連結及掃描期間有變動或無法讀取的檔案；可顯示進度並取消。
- 每組重複檔案由使用者指定保留項目，確認後逐筆移至 Nanako 資源回收桶；服務端會重新驗證內容與檔案狀態，並逐筆記錄操作結果。
- 讀取權限可掃描，寫入權限才可整理；掃描工作僅能由建立工作的使用者讀取。
- 僅使用 Node.js 內建模組，不增加第三方相依套件。

## 範圍與安全原則

- 僅掃描可攜式目錄中的 `NanakoData` 管理檔案；不得提供選取其他磁碟、Windows 使用者資料夾或任意路徑的功能。
- 掃描預設為唯讀，不改名、不移動、不刪除檔案。
- 不以檔名或檔案大小單獨判定重複。先以大小篩選，再以串流內容雜湊比對；同名但內容不同的檔案不得視為重複。
- 不自動決定保留哪一份。每組至少保留一份，使用者逐組選擇保留項目及要整理的副本。
- 使用者確認整理後，將所選副本移入 Nanako 資源回收桶，保留還原能力；不得直接永久刪除或覆寫保留項目。
- 不跟隨符號連結、junction 或其他離開 `NanakoData` 的路徑。加密空間先排除於第一版掃描範圍，另行設計解鎖與明文比對規則。
- 遵守登入身分與資料空間讀寫權限；唯讀使用者不可執行整理。掃描及每筆整理結果應寫入操作紀錄，支援取消、進度與失敗結果。

## 建議操作流程

1. 從檔案管理器的「檔案去重」入口開始；明確顯示掃描範圍為 Nanako 管理的資料空間，不出現作業系統資料夾挑選器。
2. 掃描前說明會讀取檔案內容以計算雜湊，不會上傳或變更檔案；提供開始與取消控制。
3. 以檔案大小分組候選項目，再串流計算 SHA-256。掃描中顯示進度及可取消狀態，不將整個檔案載入記憶體。
4. 顯示每個重複群組的檔名、Nanako 相對路徑、大小、修改時間及候選可回收容量。重複群組必須讓使用者明確標記保留項目。
5. 顯示待移入資源回收桶的項目與預估容量，要求確認後才逐項執行；任何錯誤都保留原檔並顯示部分成功／失敗結果。
6. 完成後提供前往資源回收桶與還原入口；操作紀錄記載掃描狀態及每筆移動結果。

## 驗收條件

- 不同檔名但內容相同可被同組識別；同名但內容不同、同大小但內容不同不得誤判。
- 支援空檔、大型檔案與取消掃描；雜湊採串流處理，記憶體用量不隨單一檔案大小線性增加。
- 掃描期間檔案被修改、移除或讀取失敗時，該項目不會被錯誤整理，且結果可辨識。
- 符號連結、junction、路徑跳脫、資源回收桶及 Nanako 管理資料以外的路徑均不會被掃描或變更。
- 整理前必須人工選擇保留項並確認；整理後可由資源回收桶還原，唯讀使用者不得整理。
- 有重複內容的照片、影片或其他媒體若在相簿／播放清單被引用，移入資源回收桶後的引用行為須一併驗證。

## 相依套件

目前使用 Node.js 內建 `crypto` 與串流檔案 API；沒有新增套件，因此不更新 `THIRD_PARTY.md`。若效能或演算法需求改變，須在真正新增套件時再評估授權、版本與封裝狀態。
